# v0.2.0 计划：校验 Cloudflare Access JWT（A+）

> 状态：**计划稿**，未实现。适用基线 DSH `0.2.1-rc.2`；v0.1.0 已在 test 实例通过门禁（见 CHANGELOG 与顶层仓库 2026-10-24 gitlink 提交说明）。

## 为什么要有这一版

v0.1.0 的判据只有“断言头存在且非空”。安全性完全由部署事实承担：**origin 只能经边缘代理到达**。这条在本机站不住：
cloudflared 自己也从 `127.0.0.1` 连到 DSH，所以无法按来源地址区分“边缘代理”与“本机任意进程”——能直连监听端口的本机进程
自带该头即可拿到 owner peer。v0.2.0 把“信任断言存在”升级为“信任**可验证**的断言”，堵掉这一条。

## 非目标（本版不做）

- 不改 401/403 语义：v0.1.0 已定的“只把 401 放大、403 围栏原样返回”不变。
- 不动 `GET /connect` 的程序化 API operator 认证，不碰 Host/Origin 围栏与 loopback 设置写权限。
- 不引入任何 npm 运行时依赖：验签用 `node:crypto`（`crypto.createPublicKey({ format: 'jwk' })` + `crypto.verify`）。
- 不承担 Access 的策略判断（谁能进由边缘决定），本版只回答“这条请求是否确实经过该 Access 应用”。

## 配置（新增必填项，即破坏性变更 ⇒ 0.2.0）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `header` | `cf-access-jwt-assertion` | 沿用 v0.1.0 |
| `teamDomain` | 无（必填） | Access 团队域名，如 `example.cloudflareaccess.com`；用于拼 `iss` 与 JWKS 端点 |
| `audience` | 无（必填） | 该 Access 应用的 AUD tag（Application → Overview 里的 Application Audience (AUD) Tag） |
| `clockSkewSeconds` | `60` | `exp`/`nbf` 容忍偏差。本机曾出现时钟慢 ~70 s 的事故（见 `.local/agent-notes.md`），偏差超限时应提醒而不是静默放宽 |
| `jwksMaxStaleSeconds` | `300` | JWKS 拉取失败时允许沿用 last-known-good 的时长上限 |

**配置缺失时的行为必须 fail-loud**：缺少 `teamDomain`/`audience` 直接拒绝加载。否则会出现“以为开了验签、实际只是查了头存在”
的静默降级——这正是 v0.1.0 之后最需要避免的错误认知。

## 验签流程（全部通过才算断言成立）

1. 取头值，按 `.` 切三段；段数不为 3 ⇒ 不算断言。
2. `header.alg` 白名单**只有 `RS256`**（显式拒绝 `none`、`HS256` 与任何非对称混淆）。
3. `kid` → 从 JWKS 选公钥；找不到对应 `kid` 时**强制刷新一次** JWKS 再判定（应对 key rotation），仍无则不算断言。
4. `crypto.verify('RSA-SHA256', Buffer.from(`${h}.${p}`), publicKey, signature)`。
5. claims：`iss === 'https://' + teamDomain`、`aud` 包含 `audience`（字符串或数组两种形状）、`exp`/`nbf` 按 `clockSkewSeconds` 判定、
   `type === 'app'`（若 Access 断言里给出）不满足则不算断言。
6. 以上全过 ⇒ 与 v0.1.0 相同地放大为 `browserPeer`。

**任何异常都不放行**：网络失败、JWKS 解析失败、时钟超偏、未知 `kid`、算法不符，一律退化为“没有断言”，走原来的 401 路径。

## JWKS 获取与缓存

- 端点：`https://<teamDomain>/cdn-cgi/access/certs`（`keys[]` 为 JWK）。
- 懒加载 + 缓存：TTL 取响应 `Cache-Control: max-age` 与本地上限的较小值；证书轮换靠“未知 `kid` ⇒ 强制刷新一次”兜住。
- 拉取失败：缓存未过期则继续用；超过 `jwksMaxStaleSeconds` ⇒ 断言一律不认（失败关闭），并记一条 warn。
- 出网要求：origin 必须能访问 `teamDomain`。云端主机经 Cloudflare 出网没问题，本机验证时要显式确认这一点（**待验**）。

## 观测

- 成功/失败分类计数（`alg 不符`、`签名不符`、`iss 不符`、`aud 不符`、`expired`、`unknown kid`、`jwks unavailable`）走 `ctx.logger`，
  warn 级按“原因 + kid”做每分钟一条的限流，避免被扫描流量刷爆日志。
- 不做指标导出、不加设置页控件（沿用 v0.1.0 的“无 Client 半区”形态）。

## 分层与测试

- `src/core/` 新增纯函数：`parseCompactJws`、`selectKey`、`verifySignature`（注入 verify 实现以便裸 Node 测试）、
  `checkClaims`；不 import cordis / `@deepseek-ai/*`。
- 单测用 `node:crypto` 现场生成 RSA 密钥对造真实签名，覆盖：正常通过、签名不符、`alg: none`/`HS256`、`exp` 过期、
  `nbf` 未来、`aud` 不匹配、`iss` 不匹配、未知 `kid` 触发一次刷新、JWKS 不可用。
- adapter 层只负责“取头 → 调 core → 结果接线到 `admit`/`authorizeIndex`”，与 v0.1.0 相同的自有属性装饰与撤除路径
  （撤除判身份走 `Object.getOwnPropertyDescriptor`，见 README 的安全边界）。

## 验收清单（test 实例，与 v0.1.0 同流程 + 以下新增）

- 真实 Access 断言（手机经 Cloudflare 访问）⇒ 200；伪造头必须全部 401：
  乱码、自签密钥签名、`alg: none`、过期 `exp`、`aud` 不匹配、`iss` 不匹配、未知 `kid`。
- 断网/`teamDomain` 不可达时 ⇒ 断言不认（401），且不影响原有 cookie 登录路径。
- 需要用户提供：`teamDomain` 与 Access 应用的 `audience`（AUD tag）。

## 风险与未知

- AUD / teamDomain 的取得与保密口径（AUD 不是秘密，但填错会直接全 401）。
- Cloudflare 的 JWKS 缓存头行为未实测；key rotation 窗口未实测。
- 本机时钟偏差（已有 70 s 事故锚点）会把 `clockSkewSeconds` 设得过大变成安全折扣，需要在验收时明确取值理由。
- 与 v0.1.0 的兼容边界：0.2.0 是破坏性变更（新增必填配置），已部署的云端配置必须同批更新后才可升级，否则插件拒绝加载。
